# 超导量子测控智能体实施方案（讨论稿）

版本：2026-11-05。对象：本仓库的超导量子自进化测控平台。本文是实施计划，不代表功能已经交付或真机通过验收。

## 1. 目标与边界

建设一套面向超导量子比特的校准系统：研究人员给出目标，系统生成可审查的实验计划，调用受控测控后端执行，依据真实数据拟合和判断，产生候选参数，复测后批准写回，并保存完整证据。首个闭环选单比特读出谐振频率扫描；之后扩展至单比特校准链和双比特 CZ 校准。

QuaLab 提供超导测控实验函数、实时反馈和 DAG 自动执行的参考；“白泽”提供自然语言目标驱动、状态监测和异常纠偏的参考。后者面向冷原子，具体实验、故障机理和参数策略不能直接移植。自主运行仅限经过验证的实验配方、参数范围与设备权限；越界、证据不足或停止未确认时转人工。

## 2. 当前基线

| 已有 | 尚缺 |
| --- | --- |
| React/TypeScript 前端；对话、蓝图、看台及接口验证台 | 真实服务端、正式认证与共享数据库 |
| 单比特 9 个、双比特 17 个执行实例的模拟流程 | 显式依赖与资源约束驱动的 DAG 调度 |
| `WorkflowGateway`、模拟状态机、审批/重试/暂停 | 真机执行适配、实时测量流和设备停止确认 |
| 离线 32 所接口封装和合成 S21 曲线 | 供应方真实合同、实验关联键、逐次原始数据与参数写回 |
| 浏览器内参数、报告、CSV 导出 | 服务端参数版本、不可覆盖运行记录和可复现报告 |
| 规则式对话 | 基于真实实验上下文的模型规划、诊断与受控工具调用 |

现有 `frontend/src/lib/apiOnly/contract.mjs` 的接口路径只是交付文档封装。`calibration/insert` 是否启动执行、状态枚举、扫描参数覆盖、结果关联、取消确认、参数发布/回读/回滚及设备互斥均须现场核实。不得将离线验证台当作真实联调结果。

## 3. 目标架构

```text
研究人员 / 前端（目标、计划审查、实时运行、证据）
                │
实验 API ── 身份/权限/审计 ── 实验与参数数据库 ── 原始数据存储
   │
工作流编排器（DAG、资源锁、重试预算、停止与恢复）
   │                         └── 智能体（检索、规划、诊断、建议）
实验执行服务（预检、配方校验、采集、拟合、质量门）
   │
设备适配层：确定性模拟器 / 供应方测控服务 / 经批准的真机
```

智能体只通过有类型、有权限的工具访问实验服务；它不直接调用板卡驱动。状态和测量的权威来源是服务端，前端只消费快照与事件。控制命令与数据采集分离，设备侧保留独立的急停/安全联锁。

## 4. 核心数据与合同

### 4.1 对象

| 对象 | 最小字段与约束 |
| --- | --- |
| `ExperimentDefinition` | `definitionId/version`、目标类型、输入参数模式及单位、上下限、依赖、所需通道/设备资源、输出数据模式、分析器版本、质量门；定义发布后不可原地改写。 |
| `CalibrationPlan` | 目标比特/耦合器、设备与拓扑版本、配方版本、DAG、策略、操作者、批准状态。 |
| `Run/Attempt` | `planId/runId/attemptId/nodeId`、服务端版本、输入快照、开始/结束时间、状态、操作者或自动决策来源；每次重试生成新 `attemptId`。 |
| `Measurement` | `attemptId`、采样序号和时间、横纵轴及单位、原始数据 URI/校验值、采集状态；部分数据可保留，不冒充完整结果。 |
| `Analysis` | 输入数据引用、拟合算法和版本、拟合参数、不确定度/残差、质量判定、失败原因。 |
| `ParameterRevision` | 目标与作用域、参数名/值/单位、基线版本、候选差异、来源 `attemptId`、批准/发布时间、回读值及回滚目标。 |
| `Decision` | 触发指标、所用证据、建议动作、参数差异、批准人或自动策略版本、执行结果。 |

### 4.2 服务端语义

- 创建计划只生成草稿；执行前预检身份、设备在线状态、目标拓扑、参数单位与范围、资源占用及数据落盘位置。
- `start/pause/stop/retry/approve/publish` 均携带幂等键、预期版本和操作者身份。重试不能批准后续节点；审批绑定具体 `attemptId`。
- 订阅提供单调事件序号，断线重连可从序号继续；较旧的 HTTP 响应不能覆盖新状态。
- 停止请求须区分“已受理”“硬件已停止”“资源已释放”。未收到后两者确认前，不启动冲突任务。
- 参数写回采取候选、检查、批准、发布、设备回读、必要时回滚的顺序。发布与历史运行记录不得互相覆盖。
- 真实测量和浏览器模拟数据有不同 `dataSource` 与验收级别；报告、图表和导出沿用该标识。

建议 API 先稳定语义再定 URL：`plans` 创建/读取；`runs` 启动/控制；`runs/{id}/events` 订阅；`attempts/{id}/measurements` 读取；`analyses` 查询；`parameters/candidates` 提交与审批；`parameters/revisions` 发布、回读和回滚。先与 32 所现有接口逐项映射，缺口由适配服务补齐，不在前端猜测字段。

## 5. 实施阶段与验收门槛

工期为排期估算，前提是测控接口、设备权限、实验人员和测试环境可获得；各阶段以验收结果推进，不以日期代替验收。

| 阶段 | 预计 | 工作与产物 | 退出条件 |
| --- | --- | --- | --- |
| A. 合同与实验基线 | 2–3 周 | 与测控团队核对接口/状态枚举/数据格式/停止语义；确定读出扫描的参数单位、允许范围、拟合与质量门；形成接口合同、设备资源图和样本数据集。 | 一次人工实验能把请求、任务、原始数据、结果和硬件停止确认关联起来；不确定项明确列为阻塞。 |
| B. 单项实验纵向闭环 | 4–6 周 | 实施服务端 Run/Attempt/Measurement、只读实时事件、原始数据归档、拟合服务；前端接入真实 `WorkflowGateway` 和实测图。先用确定性模拟器，再在授权设备执行。 | 同一输入可复现模拟结果；真机运行可从 `runId` 找回输入、原始数据、拟合、日志与状态；断线重连不丢最终结果。 |
| C. DAG 与参数治理 | 4–6 周 | 将 9/17 个执行实例转为版本化实验定义；建立依赖、资源锁、重试预算、候选参数、审批/发布/回读/回滚。先完成单比特链。 | 无依赖抢跑或资源冲突；故障/暂停/取消后资源释放可验证；参数更新可追溯且能回滚。 |
| D. 智能体辅助 | 3–5 周 | 自然语言转结构化计划；检索当前实验、历史基线和手册；输出带证据的诊断与候选参数；人工确认执行。 | 计划通过模式和物理范围校验；诊断能引用测量/历史依据；模型失败不影响底层停止与运行状态。 |
| E. 受限自主校准 | 4–6 周 | 对少数已验证故障模式开放自动复测与范围内调参；加入最大步数、时长、资源与失败预算，异常升级人工。 | 在预先冻结的模拟回放集和受控真机试验中达到团队约定指标；所有动作可回放，越界与停机故障按预期阻断。 |

若 A 阶段发现供应方没有逐次参数覆盖、原始数据关联或停止确认能力，优先补适配服务/测控接口，B–E 的真机范围同步收窄；不能用界面模拟替代验收。

## 6. 首个用例：单比特读出频率扫描

1. 用户选择目标比特及目标设备，或输入“检查 Q12 的读出频率”；系统形成结构化计划，显示扫描范围、步长、功率、采集次数、预估资源和质量门。
2. 服务端解析比特到读出通道的拓扑映射，校验范围、单位、设备占用和用户权限，保存不可变输入快照。
3. 执行服务采集 S21/IQ 原始数据，流式推送采样进度；异常或取消时按设备合同停止并确认资源释放。
4. 分析器按已批准的算法版本拟合谐振峰，记录残差、不确定度和拟合失败原因；不以曲线极小值直接冒充正式拟合。
5. 与当前参数和历史基线比较，形成候选频率；超出范围或质量门不通过时进入人工处理。范围内的候选值先复测，再批准发布、回读。
6. 归档两次 `attemptId` 的原始数据、参数快照、拟合与决策；报告说明来源是模拟器还是目标实机。

最小现场验收场景：正常完成、无峰/多峰、采集中断、重复启动、断线重连、取消但设备未停止、两人同时争用设备、参数发布后回读不一致。每个场景都要确认结果归属、资源状态和审计记录。

## 7. 智能体策略

第一版只做“计划与解释”：把用户目标映射为已发布实验配方，展示参数来源和待确认项；依据真实结果生成分析摘要。第二版做“建议与复测”：针对已验证故障分类提出候选调整，必须给出证据、预期效果、允许范围和停止条件。第三版才开放“受限自主”：仅在团队批准的设备、比特、配方和参数白名单内自动执行，达到预算或质量门即停止并升级。

决策评估至少记录：正确识别率、误诊率、有效复测比例、校准耗时、设备占用、人工接管次数、越界拦截率和参数回滚次数。采用历史数据回放、确定性模拟和受控真机三级评估；不以自然语言回答流畅度或演示成功次数代替物理指标。

## 10. 第一迭代的开发规格：读出谐振频率扫描

以下是建议实现的**平台内部合同 v0.1**，用于启动开发和前后端联调；它不是 32 所现有 API 的声明。所有频率统一传 Hz，时间传 ISO 8601 UTC，幅度单位在设备 Profile 中指定，数据库保留原始单位及转换记录。物理上下限必须由实验负责人按设备/芯片配置，不能采用前端演示阈值。

### 10.1 运行前配置

服务端保存 `DeviceProfile`：`deviceId`、驱动类型、固件/服务版本、可用通道、通道互斥组、采样能力、停止能力、心跳状态；保存 `TargetTopology`：芯片版本、`qubitId` 到读出谐振腔/读出通道/LO/ADC 的映射、有效期。实验定义 `readout_resonator_scan@1` 指定所需资源、输入字段、产物类型和分析器。若映射缺失、版本过期、通道占用或停止能力未验证，预检失败并返回具体原因。

扫描输入的建议结构：`centerHz`、`spanHz`、`points`、`readoutPower`（值与单位）、`averages`、`integrationWindow`（值与单位）；另有 `targetQubitId`、`deviceId`、`recipeVersion`、`parameterBaselineRevision`。参数之间校验包括 `points >= 3`、有限数、扫描上下界落入已批准 Profile、采样点数与设备上限相容；这些只是结构约束，实际允许值由现场决定。启动时解析并冻结最终频率网格，避免执行中基线参数变化改变本次输入。

### 10.2 API v0.1 请求与响应

统一错误体：`{ "error": { "code": "RESOURCE_BUSY", "message": "...", "details": {}, "retryable": false }, "requestId": "..." }`。至少区分 `INVALID_INPUT`、`TOPOLOGY_UNRESOLVED`、`RESOURCE_BUSY`、`STALE_VERSION`、`DEVICE_UNAVAILABLE`、`STOP_UNCONFIRMED`、`DATA_INCOMPLETE`、`ANALYSIS_FAILED`、`FORBIDDEN`。控制类请求带 `Idempotency-Key`；修改已有运行再带 `If-Match` 或 `expectedRevision`。同一幂等键同一载荷返回原结果，不同载荷报冲突。

```http
POST /api/v1/plans
Content-Type: application/json

{"targetQubitId":"Q12","deviceId":"device-a","recipeId":"readout_resonator_scan","recipeVersion":1,"parameters":{"centerHz":<由已批准参数或用户输入填入>,"spanHz":<待定>,"points":<待定>,"readoutPower":{"value":<待定>,"unit":"dBm"},"averages":<待定>,"integrationWindow":{"value":<待定>,"unit":"ns"}}}
```

上述尖括号是设计占位，不是合法 JSON；开发时先用实验负责人批准的模拟 Profile 填入具体样本。响应为 `planId`、`revision`、`resolvedTopologyRevision`、`resolvedParameterRevision`、`preflight`（逐项通过/失败和原因）、`estimatedResources`、`status=draft`。`POST /api/v1/plans/{planId}/runs` 启动，响应 `202` 与 `runId`、`attemptId`、`status=queued`、`revision`；只有预检通过、权限满足且资源租约获得后才可进入运行态。

```json
{
  "eventSeq": 41,
  "runId": "run-...",
  "attemptId": "attempt-...",
  "kind": "measurement.chunk",
  "occurredAt": "2026-11-05T08:00:00Z",
  "payload": {
    "dataSource": "simulator",
    "axis": {"name": "frequency", "unit": "Hz", "values": [1, 2]},
    "series": [{"name": "s21_magnitude", "unit": "dB", "values": [-20.1, -21.2]}],
    "chunkIndex": 0,
    "isFinal": false
  }
}
```

事件样本数值只说明结构，不能用作真实扫描范围。实时端点 `GET /api/v1/runs/{runId}/events?after=<eventSeq>` 可用 SSE；事件至少包括 `run.status`、`measurement.chunk`、`analysis.completed/failed`、`parameter.candidate_created`、`device.stop_confirmed`。消费者对 `(runId,eventSeq)` 去重，检测缺号时先获取 `GET /api/v1/runs/{runId}` 快照和缺失事件，再继续订阅。原始数据下载走带权限的引用，不把大数组塞入任务列表快照。

其余最小端点：`GET /api/v1/runs/{runId}` 返回状态、revision、attempt 与产物引用；`POST /api/v1/runs/{runId}/stop` 请求停止；`GET /api/v1/attempts/{attemptId}/measurements` 获取元数据与数据引用；`GET /api/v1/attempts/{attemptId}/analysis` 获取拟合与质量门；`POST /api/v1/parameter-candidates` 创建候选；`POST .../{id}/approve` 批准；`POST .../{id}/publish` 写回；`GET .../{id}/readback` 验证；`POST .../{id}/rollback` 回滚。接口实现前先生成 OpenAPI 文档和契约样例，前端以生成类型或共享 schema 消费。

### 10.3 状态转换

计划：`draft → preflight_passed → queued → running → analyzing → awaiting_decision → completed`。允许 `queued/running/analyzing → stopping → stopped`；运行或分析错误进入 `failed`，且保留已采数据。`stopping` 不代表设备安全停止，只有设备确认、资源租约释放且审计落库后进入 `stopped`。超时无确认进入 `stop_unconfirmed`，冻结互斥资源并通知值守人员。运行不允许从 `completed/stopped` 直接恢复；重试创建新的 Attempt，由明确的 Run 或计划关联。

单节点成功仅表示该实验执行完成，质量门结果单独为 `pass/fail/inconclusive`。拟合失败或数据缺失为 `inconclusive`；不能把 HTTP 成功当作校准成功。DAG 下游仅在依赖节点的指定产物和质量门满足时就绪；“接受低指标继续”必须成为可审计的人工覆盖决策。

## 11. 数据库与归档设计

第一版建议采用事务型数据库存元数据与事件，原始波形/扫描点放对象存储或有校验值的文件存储。表名仅作为建议，迁移脚本应写进正式后端仓库。

| 表/存储 | 必要键、索引及约束 |
| --- | --- |
| `experiment_definitions` | `(id,version)` 唯一，定义 JSON schema/资源/依赖及发布状态。 |
| `device_profiles`、`target_topologies` | `(id,revision)` 唯一；运行引用确定版本，修改不回写历史。 |
| `plans`、`plan_nodes` | `plan_id` 主键；节点有 `definition_id/version`、依赖、目标和策略。 |
| `runs`、`attempts` | `run_id`、`attempt_id` 主键；`attempts(run_id,node_id,attempt_no)` 唯一；保存输入快照、状态、revision、设备租约和起止时间。 |
| `run_events` | `(run_id,event_seq)` 唯一且单调；记录 actor、type、payload、时间，追加写。 |
| `measurement_artifacts` | `artifact_id`、`attempt_id`、URI、SHA-256、格式、大小、采样范围、完成标记；不得覆盖已发布对象。 |
| `analyses` | `analysis_id`、`attempt_id`、输入 artifact 校验值、算法版本、输出、不确定度、质量门。 |
| `parameter_revisions`、`parameter_candidates` | 目标、作用域、name、unit、revision、基线版本、来源 attempt、审批与设备回读；发布使用乐观并发控制。 |
| `idempotency_records`、`device_leases` | 幂等键按用户/端点作用域唯一；资源锁按互斥组唯一，租约续期和故障冻结可查询。 |

事件、运行快照和参数发布应在同一事务或可靠 outbox 中提交；若数据文件已写但元数据提交失败，标记待清理，不展示为正式结果。原始数据的保存年限、备份位置、脱敏和权限由现场单位确定。导出的报告至少包含设备/拓扑/配方/分析器版本、所有 Attempt、数据哈希和参数发布历史。

## 12. DAG 定义与调度算法

先把现有 `simulator.ts` 中的节点名称迁移为版本化定义，节点 ID 与实验类型分离：`IqToProbabilityRetest` 是执行节点 ID，实验定义仍是 `IqToProbability`。单比特主链为 `ReadoutFreqDip → F01Spectroscopy → XYGateAmpRabiImpl → IqToProbability → ReadoutParaSweepByIQProb → IqToProbabilityRetest`；`T1Idle/T2CPMG/RB1QCal` 的依赖按校准手册由实验负责人确认，不能凭前端数组顺序推断。双比特 CZ 链的依赖、可并行条件、耦合器资源和两端比特前置质量门也须单独签核。

调度器每次读取计划快照，找出所有前置条件已满足、未运行且未终止的节点；为每个候选节点解析资源集合，按确定性顺序申请互斥租约，成功后创建 Attempt 并入队。资源释放须以执行器回执为准；取消、进程崩溃和租约过期要有恢复扫描。失败重试只在预算内创建新 Attempt，且不能自动越过质量门。每次调度决定记录输入事件序号和策略版本，以便离线回放。

## 13. 拟合、质量门与智能体工具

S21 首版分析器输入必须是带单位、采样时间、完整性标识和校验值的实际采集数据。分析流程：格式/点数/有限值检查 → 标记缺点/异常点 → 按实验团队选定模型拟合 → 输出中心频率、置信度或不确定度、残差与诊断标记 → 与当前参数和历史基线比较 → 生成候选。多峰、无显著峰、边界峰、拟合不稳定或数据不足均返回 `inconclusive`，不强行给出可发布频率。分析算法、判定阈值、允许变更幅度和复测规则由实验负责人批准并版本化。

智能体工具白名单建议为 `get_plan`、`get_run`、`get_measurement_summary`、`get_parameter_history`、`propose_plan`、`propose_parameter_candidate`、`request_retest`。前四个只读；后三个产生提案或经授权的受控动作。工具层校验用户、设备、目标、配方、参数范围、剩余预算及请求版本；模型输出先解析为 schema，不接受任意脚本或驱动命令。诊断记录必须包含引用的 `attemptId/artifactId/analysisId`、假设、备选原因、建议值、预期变化、停止条件和置信度来源。没有证据时返回“无法判断”并请求人工检查。

受限自主策略建议按实验逐项授权：最大尝试次数、单次/累计参数变化、最大运行时长、失败率门槛、设备健康门槛、允许的自动写回范围。第一阶段默认**不自动发布参数**；即使允许自动复测，发布仍需批准。任何设备告警、拓扑版本变化、停止未确认或越界提案都终止自主链并转人工。

## 18. Vibe Calibration 论文对方案的修订

参考：[Xu 等，*Vibe Calibration: Autonomous Bring-up of a 112-Qubit Superconducting Quantum Processor by a Skill-Orchestrating Language Agent*，arXiv:2606.22376](https://arxiv.org/html/2606.22376)。论文作者来自北京量子院、物理所等机构；其方法与本项目的超导量子校准高度相关。论文报告了在 112 比特可调频 transmon 处理器上自主完成 108 个比特的校准，用时 4.7 小时，并在 16 比特子集上与专家手动结果 14/16 一致。这些是论文实验结果，不能作为本项目验收指标或已实现能力。

### 18.1 从 DAG 升级为有质量门的 Skill 决策树

论文将现有 qulab/quarkstudio 测控脚本包裹为五层：① 编排决策树；② 参数化测量命令；③ 设备配置适配；④ 拟合与物理检查的质量门；⑤ 记录结果 ID、图、数组、拟合值与后续动作的审计。原有底层测量代码保持独立。对本项目而言，第 12 节的 DAG 只描述依赖与资源；还需给每个实验节点增加 `accept/retry/skip/rollback/human_review` 类型化边，并记录触发边的证据。

首批 Skill 包装顺序：`ReadoutFreqDip`（S21）→ `F01Spectroscopy`（频谱）→ `XYGateAmpRabiImpl` 拆分为跃迁验证与幅度校准的两个实验定义 → `IqToProbability` 与读取优化 → `T1Idle/T2CPMG/RB1QCal`。论文的 time-Rabi、power-Rabi、Ramsey 等节点与当前 9/17 节点**不是一一同名对应**；先由实验负责人对照本仓库校准手册确认是否拆分、增补或重排，不能只改显示名称。双比特 CZ 链保留为后续独立 Skill 集。

| Skill 字段 | 工程语义 | S21 首版落点 |
| --- | --- | --- |
| `intent/motivation` | 本次测量为何执行，引用哪项前置证据 | 计划请求强制填写意图；审计中保留。 |
| `command/arguments` | 有类型的参数化命令，不能让模型拼接驱动脚本 | `readout_resonator_scan` + 频率网格/点数；真机字段待核实。 |
| `expectedArtifacts` | 结果 ID、原始数组、拟合、图和配置快照 | 当前模拟服务有点列、分析、哈希；图和独立文件存储待做。 |
| `gate` | 依据数值和物理检查给出接受或失败 | 当前仅有模拟质量门；现场拟合和阈值待实验负责人签核。 |
| `edges` | 接受、修改扫描重试、回退、跳过、人工检查 | 当前实现决策记录；自动执行回退边尚未启用。 |
| `audit` | 固定输入、测量、拟合、决策及下一动作 | `run.events` 和 SHA-256；正式服务需独立持久化。 |

论文中 S21 使用谐振凹陷相对噪声的显著性门；还给出 Rabi/Ramsey 拟合的 R²、每周期采样数和 SNR 门，以及通过门后才允许参数写回。**这些数值依赖论文的设备、噪声模型和采样条件。** 本项目应把阈值放入经实验负责人批准的、按芯片与设备版本生效的 Gate Profile；在现场数据回放中评估误判和漏判后再启用。现有 `discrete-minimum-demo-v1` 只产生模拟候选，不算论文级拟合，也不允许写回。

### 18.2 两条器件路线与回退边

固定频率或已预设磁通偏置的器件可从 1D S21、单比特频谱进入共用表征链。可调频器件须先评估 S21-vs-flux、spectrum-vs-flux、频谱脊线拟合和磁通安排，再进入共用链。论文的回退示例包括：time-Rabi 比值不符合 0→1 跃迁时回到频谱，磁通脊线歧义时回到二维频谱，T1/Ramsey 发现频率大幅漂移或上游状态失效时回到拓扑分组/重新表征。平台需把每条回退边写成可测试规则，限制最多回退次数和设备占用预算；未定义的异常进入人工检查。

多比特并行分组应由测控后端公布的芯片拓扑和共享资源限制决定，Agent 不能凭曲线自行猜测哪些比特可同时测量。每个分组内还要逐比特检查上游参数是否有效，失败比特从下游批次中剔除并留下原因；不能因同组其他比特通过而批量发布参数。

### 18.3 人机协作与数据集建设

采用论文的三阶段路径，但以本项目设备规模和资源重新定验收：**人工监督单比特**，专家逐次审核图与数值并确认 Skill v1；**半自主小规模**，系统处理已知情况，未知错误呼叫专家并把修复过程形成 Skill v2 的候选变更；**跨芯片验证**，冻结 Skill 版本，在未参与编写规则的目标芯片上评估迁移，不在验证时暗中修改规则。

每次轨迹至少保存：用户目标、Skill/工具 schema 版本、模型与提示版本、决策前上下文、参数化命令、设备返回、原始数据引用、拟合/门判断、专家最终决定和修改理由。训练集仅纳入专家核准轨迹，并按芯片/时间分组切分，避免同一实验的近重复样本同时进入训练与测试。先评估基础模型严格遵循 Skill 的能力，只有数据量、错误分析和收益支持时再微调；论文使用的具体模型与训练参数不直接照搬。

模型评估除校准质量外，增加 **Skill adherence**：是否读取正确版本、是否按边转移、是否越权改参数、是否跳过质量门、是否正确升级未知故障；同时报告专家一致率、各类失败率、时间/设备占用、回退次数和证据完整率。模型不能仅凭声称“校准完成”通过验收。

### 18.4 对当前开发迭代的直接影响

`backend/src/skills/readout-s21.mjs` 已建立第一份模拟 Skill 元数据与纯决策函数。正常扫描形成 `accept_candidate`，边界极小值可提出 `retry_wider_scan`，证据不完整进入 `human_review`；执行器只记录 `skill.decision`，**不自动执行重试和参数发布**。下一开发任务按顺序为：① 将 Skill 定义、Gate Profile、设备配置适配和算法版本独立持久化；② 用专家标注的真实 S21 数据替换演示质量门；③ 为重试/回退增加有预算的调度执行和审计；④ 用单比特人工监督轨迹评估 Agent 的 Skill 遵循性；⑤ 再逐步扩至多比特拓扑分组。

当前模拟切片又增加了 `follow-up-plan`：边界极小值的 `retry_wider_scan` 决策可以创建扩大范围的复扫计划，计划保存来源 `runId`、原始数据哈希和复测层级，最多四层。前端 `#api` 页可显式发起边界异常并按 Skill 建议复扫。这里是模拟恢复路径验证；真机自动重试、参数发布和质量门仍须另行验收。

本机链路验证：以 1 MHz 扫描范围开始，四次运行依次使用 1、2、4、8 MHz；前三次由 `BOUNDARY_MINIMUM` 走 `retry_wider_scan`，第四次通过模拟质量门。每次计划与前次运行及数据哈希关联。该结果仅证明模拟决策树与接口合同，不证明真实谐振峰判别性能。

## 19. P1/P2 模拟阶段进度与下一步

**P1 参数治理原型**：`backend/src/parameters.mjs` 增加了质量门后候选、模拟审批、基线版本检查、模拟发布/回读和追加式回滚。候选引用 `runId/attemptId/数据哈希/分析方法`；失败或不完整的运行无法生成候选。`#api` 页可以演练这条链。审批人只是本地演示输入，回读来自模拟参数库，不代表正式身份验证或设备读回。下一步应接正式认证、权限、设备读回及失败补偿，随后在真实 S21 数据上验收质量门。

**P2 拓扑与 DAG 原型**：`backend/src/recipes.mjs` 定义 Q12、Q13 的共享读出资源和相邻关系，提供单比特及 CZ 的只读规划图、依赖检查和资源安全的就绪批次选择。现有前端双比特演示是 9 个单比特前置实例加 8 个 CZ 实例，共 17 个；正式双比特规划必须分别确认两个比特的上游状态，因此模拟规划图为 Q12 的 9 项、Q13 的 9 项和 CZ 的 8 项，共 **26 个规划节点**。这不是对原前端流程的静默替换；实验负责人仍需签核两端比特和耦合器的真实依赖、配方与资源映射。当前没有执行后续 25 项的测控适配或质量门。

**P2 智能体边界原型**：`backend/src/agent.mjs` 提供确定性目标预览和只读/提案工具白名单；`#api` 页可输入目标并看到对应模拟规划图。没有模型推理、实验诊断或自主设备执行。下一步需先用专家审核轨迹和真实数据建立 Skill 遵循性评测，再接模型服务，模型输出只能经类型校验与工具权限层进入执行系统。

优先开发顺序：① 用现场 S21 数据替换演示分析与质量门；② 完成服务端认证和参数写回/回读适配；③ 分别为 Q12、Q13 的频谱、Rabi、读出、相干测量提供参数化命令及分析器；④ 对 CZ 八项增加耦合器资源、质量门和回退边；⑤ 以冻结的 Skill 版本评估 Agent 并逐步开放受限自主。当前所有 P1/P2 原型均标记 `dataSource=simulator`。

## 20. 后续迭代：F01 频谱模拟纵切

已为 Q12 增加版本化 `f01-spectrum` Skill 与 `f01_spectroscopy` 计划合同。频谱计划只能引用**当前已发布**、且含来源 S21 测量哈希的读出参数版本；计划冻结版本号、读出值、来源运行和产物 SHA-256，启动前再检查版本。参数版本发生变化后，旧频谱计划须重新创建。采样、离散峰值分析、质量门、事件、产物哈希和扩大扫描建议都走现有运行状态机；前端从已发布的 S21 候选进入 F01，并显示上游版本及产物哈希。F01 候选被明确限制在模拟结果，不能调用读出参数候选发布接口。

这一步只验证跨 Skill 的参数来源与执行门，不构成真实频谱校准。下一开发门槛是现场设备合同、原始 IQ/频谱数据、0→1 跃迁验证方法和实验负责人签核的频率范围/资源映射；拿到这些后替换模拟采样与离散峰值质量门，再做现场回放和受控硬件联调。Rabi、相干测量、双比特 CZ 仍停留在规划图，未接入此运行状态机。

## 21. 无真机条件下的设备接入仿真

现场真机尚不可用，因此以 `simulated-controller-v1` 实现设备适配边界，模拟采样块回执、停止确认、读出参数写入和回读。服务健康状态及适配器描述始终声明 `hardwareConnected=false`，所有数据仍标记 `dataSource=simulator`。可注入采集中断、停止未确认和回读不一致：采集中断产生不完整产物及失败事件；停止未确认保持 `stopping` 和资源占用，重启后也不自动释放，直到显式重试得到回执；回读不一致阻止参数版本发布。前端展示适配器状态并提供停止重试入口。

后续开发可以继续使用此模拟适配器验证流程、审计与恢复，但不能将模拟回执记为真机验收。替换真实驱动时需保持同一接口语义，并用现场设备确认命令超时、重复请求、设备状态查询、写入补偿及重启后的停止状态；真机缺席期间只记录这些为待验收项。

## 22. 蓝图范围与流水线呈现

蓝图版参考 `E:\work\QuantaMind` 的模板选择、阶段进度和执行时间线交互，但 `1bitV2.00` 原流水线包含芯片设计、仿真和工艺任务，本项目的“单比特校准蓝图”沿用自己的 9 个测控校准节点，不把芯片设计步骤混入校准。用户选择单比特蓝图后，新建表单锁定单比特类型；该任务的画布、阶段和时间线只显示单比特节点。任务对话的快捷指令与计划生成也受蓝图范围约束，要求双比特 CZ 的指令会被拒绝并提示另选蓝图。双比特任务同理必须从双比特蓝图进入；切换蓝图会新建独立任务，不修改已有任务的实验类型。
