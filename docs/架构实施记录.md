# 超导量子测控架构实施记录

## 权威边界

远程模式由 QuantaMind `/api/v1/calibration` 管理工作流、权限、版本和审计。本仓 `backend/` 是只监听本机的实验模拟切片；`#api` 仅在非远程模式连接它。两者的运行 ID 和参数库仍是不同命名空间，不得合并展示或互相宣称已发布。

本仓计划请求现要求 `blueprintId` 与 `blueprintVersion`。服务端将蓝图、目标和技能一起校验；扩大扫描的后续计划继承原蓝图。Agent 预览同样要求蓝图范围，单比特蓝图不能规划 CZ。QuantaMind 的远程创建请求携带同样字段；其服务端验证蓝图与实验类型一致，拒绝未知版本。已有客户端可暂时省略字段，服务端会按实验类型处理旧请求。

## 模拟设备命令

S21/F01 采集及停止命令在下发前记录 `device.command_requested`，回执记录 `device.command_acknowledged`；设备错误和停止未确认携带 `commandId`。进程恢复时，缺少回执的请求标记为 `device.command_outcome_unknown`，不自动重发。该机制只提供模拟审计语义。真机接入必须在设备控制器或适配器侧提供同一命令 ID 的去重与状态查询，且在状态未知时锁住资源直至核对完成。

QuantaMind 校准执行器已改为将一次设备测量的结果同时用于质量门和结果保存，避免同一节点尝试被调用两次。跨进程保存冲突发生在测量之后的情形仍需要真机适配器幂等命令和设备侧核对来处理。

QuantaMind 的单比特模拟适配器现在为 `ReadoutFreqDip` 和 `F01Spectroscopy` 结果附带 S21/F01 原始曲线、离散极值分析与 SHA-256。这些字段随节点结果进入权威审计记录；`publishAllowed=false`，F01 的 `sourceParameterRevision` 仍为空，明确表示尚未建立真实的上游参数发布链。

## 下一阶段的准入条件

1. 将 S21/F01 的物理拟合、候选参数和读出版本纳入 QuantaMind 的运行 ID 与数据库事务，移除业务上对本机 5290 服务的依赖。目前已有模拟原始曲线与哈希，但本机服务的候选审批和 QuantaMind 工作流参数版本仍是两套记录。
2. 为真实适配器实现命令 ID、设备回执、停止确认、启动时状态核对和参数写入前后的硬件回读。当前只有模拟适配器，不能据此声明真机安全闭环。
3. 建立固定的模拟故障用例集，覆盖采集中断、停机无回执、回读不一致、旧参数版本、重复命令与越界蓝图；发布前验证不发生跨蓝图执行和无审批参数写入。
4. 模型规划先输出结构化提案，附目标、蓝图版本、技能版本、参数范围、证据引用与预算；确定性策略验证后才能创建计划。模型不得直接调用设备或发布参数。当前规则规划器仍是确定性预览，没有接入模型服务。

本仓已提供 `POST /api/v1/agent/proposal-review` 供未来模型输出先行校验：它验证目标意图、蓝图、计划参数和尝试/时长预算，返回 `executable=false`，不会创建计划。当前尚未接入模型服务；证据引用与正式实验预算的服务器端核验仍需随权威工作流实现。

OpenClaw、LangGraph 或 Temporal 只在上述契约稳定且出现明确的会话、决策图或长任务恢复需求后评估。校准状态机和设备权限始终由领域服务控制。
