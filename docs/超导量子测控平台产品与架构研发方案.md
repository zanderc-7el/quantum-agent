# 超导量子测控平台产品与架构研发方案

版本：2026-11-06 讨论稿。目标读者：产品负责人、超导实验负责人、软件架构师、研发与测试团队。本文定义目标范围、系统边界、交付顺序和验收标准，不代表所列功能已经实现或通过真机验证。

## 1. 结论与实施原则

建设范围同时包含三份交付文档中的测控软件和云服务能力，以及本项目新增的蓝图工作流、预设专家、实验 Skill、连接器和自主校准 Agent。首个可验证产品版本以**模拟设备上的单比特 S21→F01 闭环**为纵向主线；原交付文档的其他功能进入同一产品路线图，按依赖逐步交付。真机接入另设现场合同与安全验收关口。

架构上以 QuantaMind 校准服务为正式工作流与参数记录的权威端；本仓的 React 前端逐步接入该服务，本仓 `backend/` 继续作为本机确定性模拟与合同验证工具。能力逐步收敛到同一运行 ID、同一参数版本链和同一审计链，避免同时维护两套“已发布”的业务事实。

实验 Agent 负责观察、规划、诊断与提出结构化行动；设备动作、参数写入、授权和恢复由确定性领域服务执行。预设专家、Skill、连接器均要有版本、状态、适用范围及审计记录；蓝图在运行创建时冻结它们的绑定快照，并在每次工具执行时复核权限。

## 2. 产品定义

### 2.1 用户与核心任务

| 用户 | 主要任务 | 默认权限边界 |
| --- | --- | --- |
| 超导实验研究员 | 配置基础实验、创建校准蓝图、观察曲线、比较候选参数与复测结果 | 可创建和运行获授权设备上的实验；参数发布按策略审批 |
| 测控设备运维员 | 管理仪器/通道/JPA、诊断告警、确认停止与恢复 | 可执行设备维护动作；生产设备配置变更留痕 |
| 校准负责人 | 发布 Skill/阈值、审批参数候选、决定异常接管 | 对具体设备和参数范围授权，不使用通用管理员替代 |
| 平台管理员 | 用户、组织、角色、菜单、计算资源、连接器配置 | 管理平台配置；实验数据仍受项目/租户授权约束 |
| 云服务用户 | 选择计算资源、编辑线路、提交作业、查看和分享结果 | 只访问被授予的计算资源和工作空间 |

前两个版本优先覆盖实验研究员、设备运维员和校准负责人；云服务用户体验随计算服务与线路模块上线。系统应从一开始保留项目/组织/租户、设备和数据集四层授权键，防止后期为云服务重做数据隔离。

### 2.2 产品主流程

1. 管理员配置量子计算机、芯片拓扑、通道、JPA、计算资源、连接器和账号权限。
2. 研究员在基础实验中选择实验类型与对象，配置总体参数、JPA、组、比特和耦合器，保存草稿或提交任务；可查看/下载波形与实验代码。
3. 研究员选择自动化表征或校准蓝图，使用模板、拖拽步骤与依赖、设置验收和运行策略，形成版本化计划。
4. Agent 依据蓝图、Skill、设备档案与历史证据提出下一项实验。服务端校验授权、资源、参数、预算和前置条件，调度至模拟或真实设备连接器。
5. 任务控制台实时呈现排队、运行、暂停、失败、人工接管、完成和取消状态；采集数据、拟合分析与报告进入实验数据目录。
6. 校准结果生成候选参数；经过质量验证、必要的审批、发布和设备回读后才成为生效版本。历史参数与实验数据保持可追溯。
7. 云服务用户可在授权计算服务上编辑 QASM 线路、提交作业并查看结果；运行状态由同一调度体系管理，实验与计算任务使用不同作业类型和权限策略。

## 4. 目标系统架构

### 4.1 权威边界与部署单元

```text
浏览器 React 工作台／未来云服务入口
  ├─ 实验、蓝图、专家、Skill、连接器、任务、数据、参数、审计
  └─ 线路编辑、计算服务、Cloud IDE、大屏
                 │ API / 事件订阅
QuantaMind 业务 API：身份、租户/项目、目录、工作流、审批、数据查询
                 ├─ Agent Harness：会话、上下文、工具循环、预算、证据引用
                 ├─ 领域服务：实验定义、DAG、调度、参数治理、线路作业
                 ├─ 数据服务：关系数据、原始数据对象存储、审计事件
                 └─ 设备网关：模拟器／受控现场适配器
                                      │
                       仪器与测控控制器、量子处理器
```

正式业务 API 和工作流状态集中在 QuantaMind。设备网关与 Agent 运行时可以独立进程部署，先保持清晰的模块边界，再依据负载、隔离与运维要求拆分服务。云端计算、IDE 与大屏沿用统一身份和资源目录，但使用独立作业类型、配额及运行隔离。设备控制网络与公开云入口之间通过受控网关隔离。

设计说明中的七类部件映射如下：测控软件→工作台；量子云服务→计算服务与线路作业；测控服务→实验执行与设备网关；测控实验→Skill 与分析器；测控扩展→脉冲/噪声分析插件；测控后端→任务、存储、运维；测控底座→线路、脉冲、信号与编译接口。模块边界保留，原 Java/Vue/JDK/Redis 组合不是迁移的前置条件。

### 4.2 Agent、专家、Skill 与连接器

**专家目录**保存 `expertId/version`、职责、允许的 Skill 类别、默认上下文层、模型配置、输出格式、状态及审计。首批预设：校准主 Agent、测控科学家、设备运维专家、物理诊断专家、数据分析专家。QuantaMind 现有通用领域专家可复用，但运行前要由蓝图装配出实验范围内的能力快照。专家画像不授予设备权限。

**Skill 目录**保存 `skillId/version`、实验对象、输入/输出 JSON Schema、参数单位与边界、依赖、资源需求、分析器版本、质量门、最大尝试次数、升级条件、兼容设备能力和示例。首批以 S21、F01、Rabi、IQ 判别、读取优化、T1、T2、RB 与 CZ 校准单元为核心。Markdown 指令可用于解释与操作提示；真正执行依赖版本化机器可读定义。

**连接器目录**分为提供者定义与安装实例：`connectorType/version`、`instanceId`、环境（模拟/真实）、能力清单、健康状态、凭据引用、超时、限流、资源映射、只读/控制/发布三类操作权限。首批为模拟测控设备、实验数据/原始数据、参数版本库、知识资料库；后续接现场测控接口、JPA、经典机仓与云计算资源。连接器只暴露有类型的业务操作，凭据不进入模型上下文。

**蓝图绑定**冻结 `blueprintVersion + expertVersions + skillVersions + connectorInstanceVersions + deviceProfileVersion + policyVersion`。启动前和每次工具调用前均核对目标、资源与实时状态。单比特蓝图不得调用 CZ Skill；自定义专家或第三方连接器不能扩大蓝图权限。预设项支持“内置、草稿、已发布、停用”状态及兼容性检查。

**自定义能力管理。** 专家、Skill 和连接器均开放“新建草稿→字段与合同校验→模拟环境验证→审批发布→显式绑定蓝图→停用/回滚”的产品流程。预设项只读；修改已发布项创建新版本，旧版本与既有运行快照保留。专家编辑职责、上下文、允许的 Skill 和输出合同；Skill 编辑输入/输出 JSON Schema、单位、参数边界、质量门、重试与失败策略；连接器编辑类型、接口合同、能力清单、超时和凭据**引用**。密钥只存密钥管理系统，前端与 Agent 上下文不得持有明文。发布或蓝图绑定不意味着真机连通，现场连接器仍须健康、兼容性与安全验收；运行时按冻结版本和目标范围复核。

### 4.3 Agent 运行循环与人工接管

每轮流程为：读取运行快照及证据→选择一个允许的 Skill→生成带证据引用的行动提案→策略层校验→执行→采集与分析→决定继续、缩小/扩大扫描、重试、暂停或升级人工。模型输出仅作为提案输入，不构成设备命令。

每轮记录目标、蓝图/Skill/连接器版本、输入参数与单位、证据 URI/哈希、预算、提案哈希、策略判定、命令 ID、设备回执及最终状态。预算至少包含最大轮次、实验次数、时间、设备占用和参数调整幅度；达到上限或证据不足时进入待人工处理。

自主等级按 L1 逐步确认、L2 指标达标自动推进而异常升级、L3 仅在已验证 Skill 和边界内自动运行。参数发布、设备维护及越界调整采用独立授权，不能由通用对话工具代办。只读分析可以并行；对同一设备资源的控制命令由调度器序列化。

### 4.4 执行状态与恢复语义

`Plan`、`Run`、`StepAttempt`、`DeviceCommand` 和 `ParameterRevision` 分别建模。运行状态至少包括 `draft/queued/preflight/running/awaiting_approval/paused/stopping/stopped/failed/completed/outcome_unknown`；节点尝试保留自己的输入快照和结果。停止分为请求已记录、设备已确认、资源已释放三个事件。

设备网关对每个命令使用稳定 `commandId`；提交前记录请求，超时后查询控制器状态，结果未知时锁定资源并要求核对。重试必须生成新尝试 ID，并遵守命令去重约定。参数采用 `candidate→validated→approved→publish_requested→readback_verified→active`；回读不一致进入异常状态，保留旧生效版本。当前代码中测量期间自动调用 `publish()` 的行为应先修正。

## 5. 数据架构与旧库映射

### 5.1 领域分组

附件的三库逻辑作为数据域保留：身份/配置域（原 `szkj_user`）、测控实验域（原 `szkj_measurement_control`）、云服务域（原 `szkj_quantum_platform`）。部署初期可在一个关系型数据库实例中使用独立 Schema 或清晰的表命名，权威服务通过 API 共享数据，避免跨域直接写表。最终数据库产品、版本和分库方式由部署环境确定。

| 目标实体 | 附件表线索 | 新增或修正的关键字段 |
| --- | --- | --- |
| 用户、组织、角色、授权、菜单 | `szkj_user`、`szkj_role`、`szkj_org`、权限关系表 | `tenant_id/project_id`、资源范围、审批职责、会话和审计引用 |
| 设备、拓扑、通道、JPA、配置版本 | `qt_chip_top`、`qt_coupler`、`qt_jpa`、`qt_config_template`、`qt_parameter_history` | 设备能力、资源组、版本快照、有效期、连接器实例 |
| 实验定义、草稿、模板、蓝图 | `qt_basic_experiment`、`qt_experimental_template`、`qt_basic_experiment_linker` | 独立的定义版本和运行快照；DAG 边、Skill 版本、schema 哈希 |
| 运行、节点尝试、任务 | `qt_calibration`、`qt_calibration_item`、`qt_task`、`qt_task_group` | 单调修订、幂等键、预算、资源租约、命令 ID、结果未知态 |
| 原始测量、分析、校准结果 | `qt_experimental_data`、`qt_calibration_process_result`、`qt_calibration_result`、`qt_data_analysis` | 对象存储 URI、SHA-256、单位、分析器版本、不确定度、来源参数版本 |
| 数据目录、分享、回收站 | `data_disk`、`data_disk_share`、`data_disk_recycle_bin` | 所有权、分享有效期/撤销、7 天删除期限、审计引用保护 |
| 线路、计算作业、工作空间 | `qt_line`、`qt_task`、`qt_quantum_data`、`qt_workspace` | 线路版本、QASM 版本、计算资源、作业配额、租户隔离 |
| Agent 决策与目录 | 附件未定义 | `expert_version`、`skill_version`、`connector_instance`、`blueprint_binding`、`agent_turn`、`proposal`、`policy_decision`、`approval` |

历史附件表用于迁移映射，不能因新实体出现而删除既有业务数据。实际迁移按“盘点字段与样本→确定主键/关联→双读核对→导入→校验→切换→保留回退窗口”实施。对附件中 `qt_basic_exepriment` 与 `qt_basic_experiment` 等命名差异建立显式映射，不以拼写相似自动合并。

### 5.2 存储与可追溯性

关系数据保存索引、状态、版本和授权；曲线、热力图、散点图以及大体积原始数据保存在对象存储，数据库记录不可变 URI、校验值、采样单位与来源。用户删除数据进入 7 天回收站；被运行审计或参数发布引用的原始证据不得被普通回收流程物理清除。数据分享使用独立授权记录和到期/撤销机制。

所有外部系统通过服务 API 访问数据。回调事件先验签、去重并落入接收箱，再按任务 ID/实验 ID 关联权威运行；不会根据到达顺序覆盖更新的状态。审计事件采用追加记录，导出报告标明模拟/真实来源。

## 6. 接口、连接器与现场合同

附件定义的 5 个外部回调均纳入接口合同：线路运行状态 `QMCS-API-CALLBACK-QUANTUM-001`、基础实验结果 `BASEEXP-001`、基础实验状态 `BASEEXP-002`、基础实验分析 `BASEEXP-003`、表征/校准结果 `CHAR-AND-CALI-001`。每个回调需补充请求/响应 Schema、签名/鉴权、事件 ID、幂等语义、时间戳、重放保护、错误重试与归属关系。附件“发送方主动调用接收方以获取结果”的描述存在方向歧义，现场联调前须以可执行示例定稿。

内部接口保留量子任务与硬件测控 `QMCS-API-INTERNAL-QUANTUM-001`、统一日志 `LOG-001`、脉冲信号生成 `CORE-PULSE-SIGNAL-001`。新增设备网关合同需明确：设备能力发现、预检、执行、进度、停止确认、状态核对、参数写入与回读、错误分类和资源释放。接口版本与单位由合同管理，不让前端或模型猜测字段。

云计算作业、Jupyter/VS Code、经典机仓监控各使用独立连接器；可共享身份、任务事件与目录服务。通用 MCP 可作为只读知识/数据连接方式，真机控制通过专用设备网关执行。

## 11. 必须定版的文档差异与风险

1. **密码存储**：需求说明出现 MD5，设计说明又描述 AES-256 加密密码，与不可逆密码存储要求冲突。采用第 7 节的现代密码哈希方案，并记录与旧库迁移规则。
2. **技术栈与部署系统**：设计说明写 Java/Python/Vue、JDK8、Redis6；需求说明同时出现 CentOS 7+、Ubuntu 24.04、MySQL 8.0.36；数据库说明写 MySQL 8.0.38。现有产品前端为 React，权威校准后端为 Python。S0 决定目标部署矩阵、数据库版本与遗留接口适配方式。
3. **表名与字段口径**：设计说明中 `qt_basic_exepriment` 与数据库说明中 `qt_basic_experiment` 不一致；部分表存在重复字段或类型描述异常。以真实 DDL/样本为准建立映射，禁止按文档直接执行建表。
4. **状态与回调**：线路、基础实验、校准的枚举及回调进度口径不同；“回调后获取结果”的文字与发送方向不清。定义统一内部状态和逐接口枚举映射，保持外部兼容。
5. **安全优先级**：需求优先级表把安全、保密和部分接口列为低。它们是任何设备执行和多用户访问的上线前置条件，按 S0 基础要求实施。
6. **容量与 SLA**：文档同时给出服务器推荐八核/16GB、测试服务器 48 核/256GB，以及 99.99% 可用性。容量和 SLA 需要指定并发数、数据量、部署拓扑和观测周期后签署。
7. **无真机现状**：真实计算服务卡片、设备大屏和硬件接口可以先有受标记的模拟数据及合同桩；现场行为必须在 H 阶段验证。未连接设备时不得显示“已校准”或“真实运行成功”。

## 12. 决策记录与近期里程碑

本方案建议立即冻结四项架构决策：QuantaMind 为正式工作流权威端；设备网关是唯一控制入口；Agent 的输出是结构化提案；专家、Skill、连接器由蓝图装配并在执行点授权。这四项决定了后续模块能否共用运行、数据和权限体系。

S0 结束时应交付：完整需求追踪表、原接口合同和现场待确认清单、旧库映射清单、能力目录 Schema、运行与参数发布状态机、威胁与故障用例、S1 的细化迭代任务。首个产品演示应展示“基础实验草稿→单比特蓝图→S21/F01 模拟运行→原始证据→候选参数→审批/回读状态→报告”，并能重放一次故障和人工接管过程。

## 13. 实验结果与理想基准对比（增量需求）

**产品行为。** 每个基础实验及蓝图节点在运行详情中提供“结果对比”：叠加目标基准与实验曲线，列出关键指标的目标、测量值、差值、不确定度和质量门；超限时显示可能原因、支持证据、反证或缺失证据、建议验证实验。采样中只显示已取得的曲线和进度，拟合与质量门完成后才给出最终判定。研究员可从任务、原始数据和报告跳转到同一对比结果，并可对原因假设添加复核结论。

**基准定义。** “理想结果”必须注明来源：物理模型预测、芯片设计目标、已批准的校准目标或历史最佳运行。默认使用与设备、比特、偏置、脉冲配置和实验协议匹配的设计目标；理论理想与工程验收门限分开展示。创建运行时冻结 `baselineId/version/hash`、模型参数、单位、适用范围和有效时间。无兼容基准时显示“无法比较”，不套用其他比特的目标值。

**计算与诊断流程。** 原始采样先完成单位和横轴对齐、坏点/缺点检查，再执行版本化拟合；输出峰位、线宽、对比度、T1/T2、保真度、泄漏率等按实验类型定义的指标。差值应给出符号、单位和拟合不确定度，质量门要考虑测量误差。诊断器以规则和物理模型生成有序假设，例如 S21 峰位漂移、Rabi 幅度失配、T1 异常衰减、CZ 泄漏；每个假设必须引用触发指标、原始证据及可区分的复测方法。Agent 只能建议复测或参数候选，不能仅凭相关性直接下发设备命令或发布参数。

**数据合同。** 新增 `BaselineSnapshot` 与 `ComparisonResult`。后者至少关联 `runId/attemptId/measurementId/analysisId`、目标版本、对齐曲线、指标差值、门限结果、诊断规则版本、假设及证据 ID。对比结果和人工复核意见采用追加式版本，保证报告可按原始运行状态回放。模拟数据必须带 `source=simulated`，并与现场采样严格区分。

**开发与验收。** S1 先完成 S21、F01、Rabi、T1 的确定性模拟对比及正常、漂移、无峰、坏点四类样本；S2 接入 CZ 和跨运行趋势。验收时逐项检查曲线单位与采样轴一致、基准版本冻结、超限原因能追到证据、证据不足时显示“待验证”、采样中不提前判定、重放得到同一结论。真机数据接入后，再以现场标准样本验证拟合与门限。
